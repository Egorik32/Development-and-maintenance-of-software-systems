# Лабораторные работы по разработке программных систем

Часть 1, работы 1.1-1.15. Вариант 12: города и парки. Группа ПИ-331.

Каждая лабораторная находится в отдельной папке `LabN_..._V12`. Используйте эти папки, а не старые объединённые проекты. В README каждой работы описаны запуск и ожидаемый результат. Условия, исходники и отчёты лежат рядом; отчёты 1.1 и 1.2 находятся в `reports`.

## Запуск в Windows

Открыть папку комплекта в VS Code, выбрать терминал PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\ЗАПУСТИТЬ_ЛАБУ.ps1 -Number 8
```

Номер принимает целое число от 1 до 15. Для веб-работ после запуска открыть напечатанный адрес `/lab1-N/`; остановить сервер через `Ctrl+C` перед следующим запуском. Другой порт: `-Number 15 -Port 8082`. Подробности: [инструкция запуска](КАК_ЗАПУСТИТЬ_НА_ПОКАЗЕ.md).

## Среда выполнения

На исходном компьютере всё уже установлено. В GitHub не загружаются многосотмегабайтные JDK, Tomcat, Scene Builder, LibreOffice и установщики. После клонирования на другой компьютер сначала подготовить `runtime` по [описанию среды](runtime/README.md). Отдельная папка лабораторной без соседних `runtime` и `tools` не является самостоятельным комплектом запуска.

Для 1.13-1.15 нужен запущенный PostgreSQL. В `src/main/java/config/config.properties` соответствующей работы проверить локальное подключение. Учебные настройки: `localhost:5432`, пользователь и пароль `postgres`, отдельные базы `cityparks_lab13`, `cityparks_lab14`, `cityparks_lab15`. Это демонстрационные настройки, не производственные секреты. Сервер Tomcat слушает только локальный адрес.

Только на новом компьютере один раз выполнить `setup_db.ps1` в нужной работе. **Скрипт сбрасывает её таблицы и записи.** Для обычного запуска или исправления кириллицы он не нужен. Базы независимы; схема импортируется как UTF-8.

## История Git

При публикации комплект помещается в `master`. История веб-этапов 1.9-1.15 сохраняется из локального репозитория 1.15: ветки `dev1`-`dev7` содержат прежнюю структуру одного веб-проекта. Итоговый коммит в `master` размещает все 15 работ по отдельным папкам. Это не означает, что JavaFX-работы исторически разрабатывались в веб-ветках.

Полные среды запуска, базы, их резервные копии и временные результаты сборки в Git не включаются. Нативный пакет 1.8 создаётся из исходников командой `run.ps1`; результат является самостоятельной папкой приложения, а не отдельным установщиком.
