# Чек лист проверки лабораторных части 1

Вариант 12: города и парки. Проверяй работы последовательно в VS Code, отмечая пункт только после своего запуска. Работающий код, отчет, показ преподавателю и сдача в Moodle являются разными результатами.

В разделах каждой лабораторной сначала указано требование, затем действие для проверки и ожидаемый результат. Дополнительные проверки надежности помечены отдельно: они не являются новыми заданиями.

## Перед проверкой

- [ ] В VS Code открыта папка `Moodle_ЛР_часть_1`, а не старая объединенная `CityParksJavaFX` или `CityParksJavaEE`.
- [ ] В терминале выбран PowerShell.
- [ ] Прочитано условие нужной работы. Для 1.3-1.15 оно находится в `ЗАДАНИЕ.txt` внутри ее папки; для 1.9-1.15 также есть оригинальный PDF и полный текст методички.
- [ ] Проверен вариант: у города есть название, статус и население; у парка есть название, тип, площадь, наличие водоема и дата постройки. Идентификаторы и связь города с парком служат для работы модели и базы.
- [ ] Для показа подготовлены исходники и отчет именно нужного этапа. Отчеты 1.1 и 1.2 находятся в общей папке `reports`, новые отчеты 1.3-1.15 находятся в папках своих лабораторных.

Если терминал находится в папке курса, запуск любой работы:

```powershell
.\ЗАПУСТИТЬ_ЛАБУ.ps1 -Number 3
```

Вместо `3` поставь число от `1` до `15`. Параметр `-Number` принимает целое число, а не `1.3`. Без параметра скрипт показывает список и принимает оба вида номера.

В корне папки курса один раз определи путь, прежде чем переходить в другие каталоги:

```powershell
$LABS = (Get-Location).Path
& "$LABS\ЗАПУСТИТЬ_ЛАБУ.ps1" -Number 3
```

Если выполнение скриптов запрещено, разрешение только для текущего терминала:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Java для запуска уже лежит в `runtime`. Для работ с базой PostgreSQL должен быть запущен. Веб-работу останавливай через `Ctrl+C` перед запуском следующей. Если сервер был запущен в фоне или не остановился, выполни `stop.ps1` из папки именно этой работы.

## Проверка Git

Повторная техническая проверка выполнена 20 октября 2026 года: 1.1-1.15 запущены, учебные примеры 1.1-1.2 проверены, JavaFX CRUD/XML и нативный пакет 1.8 проверены, веб-работы проверены через Tomcat. В 1.8 дополнительно проверить «Вид» → «Тёмная тема»: переключить оба режима, открыть редактирование и перезапустить приложение. Выбор темы должен сохраниться. Подробности и ограничения приведены в `ПРОВЕРКА_2026_10_20.md`.

В исходном локальном комплекте каждая веб-папка имеет собственный репозиторий с историей предыдущих этапов. В GitHub публикуется единый комплект: `master` содержит 15 папок, а `dev1`-`dev7` сохраняют историю веб-этапов из 1.15 в прежней структуре. Поэтому после клонирования Git-команды выполняются относительно корня общего репозитория. Наличие нескольких папок не заменяет проверку веток и коммитов.

В терминале нужной веб-папки выполнить команды ниже. Git должен быть установлен и доступен в терминале.

```powershell
$GIT = (Get-Command git -ErrorAction Stop).Source
& $GIT branch
& $GIT log --graph --oneline --all -15
& $GIT remote -v
```

- [ ] Есть нужная ветка и коммит с кодом соответствующего этапа, а не только пустая ветка с правильным названием.
- [ ] История содержит слияние там, где оно требуется заданием.
- [ ] Получено одобрение преподавателя там, где методичка связывает слияние с проверкой преподавателем. Сам факт локального слияния не подтверждает одобрения.
- [ ] Для удаленного репозитория вывод `remote -v` показывает адрес, а на самом сервере видны отправленные коммиты. Один настроенный адрес не подтверждает отправку кода.

Репозиторий для проверки: [Development-and-maintenance-of-software-systems](https://github.com/Egorik32/Development-and-maintenance-of-software-systems). При проверке открытия репозитория выбрать `master`: там должны быть все 15 папок, общий README, отчёты и протокол повторной проверки. Ветки `dev1`-`dev7` относятся к веб-проекту, а не к JavaFX-работам. Сам адрес репозитория не заменяет проверку наличия последнего коммита на сервере.
